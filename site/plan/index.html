Tetra

Tetra is the grid this chain settles. Tetra means four. Proof of attention.

An offer is a record: what it takes, how you know it was done, and a cost or a payment. The payment can be RA, USDC, or any token the offer names. You become a node by offering and by completing offers. The same relation holds at every scale we use: one person, a group of four to six, a region, the planet.

  • Passport. Who you are, where you are from, what you offer.
  • Discovery. Daily charts. A region, then a nation, then the world.
  • Recurve. Fractal governance. Small groups, representatives, chiefs.
  • Localize. House rules, the procedure for a place, a region you turn on.

RA is the daily attention currency. Level changes how much arrives. Humanity is the ledger under that grid: accounts you can say out loud, permissions that nest, storage at a fixed price, elections whose signer weights fade when the term ends. The app lives at tetra.earth. This repository is the chain. The knowbase is know.tetra.earth.

Where the repository stands

Already in the tree: a Spring 2.0 node (channeld, chan, keyd) with Savanna, EM and ED keys, the XPR-style RAM market, fractal elections, and permission epochs. Core contracts in the ra.* namespace, plus flex.token and fractal.perm. A local boot, python3 scripts/launch-devnet.py --reset. The whitepaper, Pure Liquid, the operator manual, and roundtables.

Still thin: the contract workflow is in the tree and counts when a run on main is green. There is no release tag and no shipped .deb yet. The operator manual still contains Spring callouts ([[info | Note]]) that GitHub shows as raw text. Node tests do not run in Actions yet.

What finishing means

Collaborative finish. Someone who has never been in a roundtable can find a request, follow the steps, open a pull request, and see a contract build run. That finish comes first.

Mainnet finish. An Ubuntu 22.04 binary from a tag, a green node test on that host, and a boot whose trust assumptions are written down. Those rows live in TO-DO-B4-MAINNET.md.

Passport, Discovery, and Localize stay on tetra.earth. Recurve's on-chain board is the election code here. The app is a different repository.

Order of work

1. A door

The plan, the how-to, the request list, issue forms, a pull-request template, a code of conduct, a security policy, the Tetra section in the README, and these pages. A request has five parts: area, why, where, how to implement, done when. A request without steps goes back.

2. A green contract build

Ubuntu 22.04, CDT 4.1.1, scripts/compile-contracts.sh. The script uses the same toolchain arguments as the root CMake external project and checks each shipping wasm. Done when a run on main is green.

3. A green node build

CR-1. Ubuntu 22.04, the README build, then ctest -j "$(nproc)" -LE _tests from the build directory. Parallelizable tests first.

4. A release you can install

CR-2. Tag vMAJOR.MINOR.PATCH. Publish an Ubuntu 22.04 .deb. channeld --full-version prints that version. macOS stays best-effort.

5. The queue stays the requests

New protocol work starts as a contribution request. It joins the mainnet table only when a public chain waits on it. Docs and CI stay on the request list.

6. The operator manual, one page at a time

CR-4. When you edit a page under docs/, replace a callout you touch with a paragraph or a blockquote. Leave the rest of that page's facts alone.

How to implement

  1. Read the request. If the steps are thin, improve the request before you write code.
  2. Branch from main: feature/…, fix/…, docs/….
  3. Change the smallest surface that makes the request true.
  4. Build the piece you changed. Contracts: bash scripts/compile-contracts.sh. Node: the README build, then the parallelizable ctest.
  5. Open a pull request with the template. Link the request.

The full recipes are on Contribute. Consensus, crypto, serialization, and resource limits need a slow read. Say that in the request.

Boundaries

  • Edit this repository. Leave submodule commits where they are.
  • external/Eden is a trimmed vendor. Board helpers we compile are contracts/fractal.perm.
  • Deposit credit is a trusted relayer. The steps are in contracts/ra.claim/FUTURE.md. A proving design is a new request with a written trust model, filed before any table change.
  • Social recovery is in the whitepaper. A request names the account graph and the limit check before any table is added.
  • Code permission on this chain is ra.code.
  • RAM_RESTRICTIONS is what makes payer=get_self() safe. Leave FORWARD_SETCODE off when ra must keep intercepting setcode. --no-forward-setcode also skips Savanna, because Savanna depends on that feature.
  • The release host is Ubuntu 22.04. State your OS in every bug report.

Publishing the pages

This directory is the site. site/brand/ is the Tetra chrome, copied as a set. Do not restyle it here. The workflow .github/workflows/pages.yml deploys site/ with GitHub Actions.

One setting lives in GitHub, outside git. A maintainer opens Settings → Pages → Build and deployment → Source: GitHub Actions. The next push to main that touches site/ publishes dougbutner.github.io/Humanity.

python3 -m http.server 8080 --directory site

Then open http://127.0.0.1:8080/.
