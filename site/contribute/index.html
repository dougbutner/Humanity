Before you branch

  1. Search the open requests. If none covers the work, file one. Fill in how to implement. Then build that.
  2. Fork the repository. Clone with --recursive when you will build the node. A docs-only or contract-only clone can skip submodules.
  3. Branch from main: feature/…, fix/…, docs/…, chore/….
git clone --recursive https://github.com/<you>/Humanity.git
cd Humanity
git remote add upstream https://github.com/dougbutner/Humanity.git
git checkout -b feature/short-description

A docs change

  1. Edit the page a reader actually opens. Operator facts live in docs/. Process lives in CONTRIBUTING.md, PLAN.md, and docs/contributing/.
  2. If the page contains [[info | …]], replace that callout with a paragraph or a blockquote. Leave the rest of the page's facts alone.
  3. If you changed the plan, edit site/plan/index.html in the same commit. If you changed a recipe or a request, edit this page too.
  4. When you touched site/, open it locally: python3 -m http.server 8080 --directory site.

A contract change

You need CDT 4.1.x, with cdt-cpp on PATH. The workflow installs cdt_4.1.1-1_amd64.deb from the CDT v4.1.1 release, on Ubuntu 22.04.

  1. Match the nearest contract. clang-format the C++ you touch, with the repo-root .clang-format.
  2. A new .cpp on an existing contract goes on that directory's add_contract(...). A new contract directory needs add_subdirectory in contracts/CMakeLists.txt and a CMakeLists.txt copied from the closest sibling.
  3. A new shipping wasm path goes in the list inside scripts/compile-contracts.sh.
  4. Compile. Wasm lands under build-contracts/, which is gitignored. CHANNEL_BUILD_JOBS=4 lowers the fan-out.
bash scripts/compile-contracts.sh

Boot, when you already have channeld, chan, and keyd:

python3 scripts/launch-devnet.py --reset --contracts-dir build-contracts

A full node build with -DBUILD_CONTRACTS=ON writes wasm under build/contracts/, and the launch script finds that directory on its own. Contract-only pull requests are checked by the Compile contracts workflow.

A node change

Build on Ubuntu 22.04. Prerequisites and both build styles are in the README. Some .cpp files need about 4GB of RAM. Lower -j if the compiler is killed.

From the build directory:

ctest -j "$(nproc)" -LE _tests

Boost.Test --run_test= takes the suite name from BOOST_AUTO_TEST_SUITE(). There is no node workflow yet. Adding one is CR-1. Until it exists, paste the command and the result in the pull request. Leave submodule pointers alone.

Open requests

CR-1. Ubuntu 22.04 node CI

Why. A node pull request currently ends on the author's machine. Reviewers cannot see a ctest result unless the author pastes one.

Where. A new .github/workflows/node.yml. The unpinned build is already in the README.

How.

  1. One job, ubuntu-22.04. Checkout with submodules.
  2. Install the README's unpinned packages: build-essential, cmake, git, libcurl4-openssl-dev, libgmp-dev, llvm-11-dev, python3-numpy, file, zlib1g-dev.
  3. Configure and build the way the README does. Start CHANNEL_BUILD_JOBS at 2. These units can use about 4GB each.
  4. From the build directory run ctest -j 2 -LE _tests.
  5. Leave serial tests, wasm spec tests, and long-running tests out until this job is green twice.

Done when a pull request that touches libraries/, plugins/, or programs/ shows this job, and a run on main is green.

CR-2. First tagged Ubuntu package

Why. The README tells a person to install humanity*.deb from Releases. There is no tag yet, so that path has nowhere to land.

Where. GitHub Releases, and the version string channeld --full-version already prints. Packaging is tools/reproducible.Dockerfile, or make package from the README.

How.

  1. Pick a version. v0.1.0 is enough while main is the development line. Tags are vMAJOR.MINOR.PATCH.
  2. Produce an Ubuntu 22.04 .deb from that commit.
  3. Publish it on the Release. Keep a humanity*.deb name so the README command still matches.
  4. Install it in a clean Ubuntu 22.04 container and run channeld --full-version. The line starts with the tag.

Done when the Releases page has that asset, and the version check is in the release notes.

CR-3. Keep the wasm list honest

Good first issue. The failure is loud.

Why. Compile contracts only proves the wasm paths named in scripts/compile-contracts.sh. A new contract that builds and is forgotten still looks green.

How. When you add or rename a contract target, add directory/name.wasm to the array. flex.token lives at ra.pure/flex.token.wasm. Run the script, or wait for the workflow.

Done when that list and contracts/CMakeLists.txt name the same shipping contracts. Test-only contracts under contracts/test_contracts stay off the list.

CR-4. One callout at a time

Good first issue.

Why. Pages under docs/ still contain Spring callouts, written [[info | Note]]. GitHub renders that as raw brackets.

How. Pick one page you are already reading. Replace each callout on that page with a paragraph or a blockquote that says the same thing. Do not retitle the page or rewrite facts you did not come to check.

Done when that page has zero [[info markers, and the meaning of each former callout is still on the page.

The pull request

Use the template. Link the issue. Say the command you ran. One maintainer approval is the usual bar. Consensus, crypto, serialization, and resource limits get a slower read. The contract workflow is the check that applies today.
