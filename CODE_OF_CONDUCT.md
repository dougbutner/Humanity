# Code of conduct

We review consensus-critical code for correctness. That goes better when people can stay in the thread.

- Critique the change. Leave the person intact.
- Ask when a step is missing. A request without steps goes back for the steps, in writing.
- Read the linked request before you expand a pull request into a second project.
- Consensus, keys, serialization, and resource limits get a slow read. Rushing those is how a chain forks for a typo.
- Vulnerabilities go through [SECURITY.md](./SECURITY.md). A public issue is the wrong room.

Maintainers enforce this by moderating the repository: editing a title, asking for a smaller diff, or closing a thread that has turned into abuse. Report that privately to the Tetra Grids maintainers, the same channel as a security contact.

This is the whole policy. We can lengthen it when a real case shows a hole.
